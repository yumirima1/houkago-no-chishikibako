# 考察品質の運用と検証

既存のRSS収集、本文キャッシュ、キュー、保存版、モデル、品質検査、記憶、調査課題を使います。記事数を増やすための別エンジンは設けません。

## 取得から保存まで

1. 登録済みRSS/Atom/RSS 1.0を取得し、同一本文と正規化URLを既存のDBでまとめます。
2. 主記事の本文を取得します。記事内で参照される許可ホストの資料と、保存済みの関連資料を最大3文書まで選びます。反対材料の検索は別に記録し、見つからないことを「反証がない」とは解釈しません。
3. ローカルモデルが本文を日本語で整理します。本文入力は全体6000字を各文書に配分し、切り詰めた場合は記録します。要約の各文を保存済みの主張IDへ結び付け、数字、予定・否定の消失、未知の固有名詞、原文の丸写しを検査します。
4. 原文の主張と検査済みの日本語整理を使い、見解・理由・別の説明・修正条件・資料間の一致点と相違点・関心への影響を生成します。過去の見解は現在の資料に対応するものだけ参照します。
5. 原文引用・保存版・前提IDを検査し、ノート、検査記録、記憶、未解決の問いを保存します。構造検査の成功は、意味の正しさや独立した事実確認の成功ではありません。

本文取得失敗は削除済み、アクセス制限、robots等の方針、タイムアウト、通信、抽出失敗に分けます。拒否を回避しません。公開日時、構造化された出来事の日時、取得日時は別項目です。出来事の日時が得られないときに公開日時を代入しません。

引用候補の文分割では、引用符内の感嘆符・疑問符を単独の主張の境界にしません。「知る！つくる！あそぶ！」のような催事名と、その外の開催日・開催予定を同じ原文の文として保持します。原文に文字を補いません。独立した次の文や英語の既存の略語処理を保つ回帰も行います。

URLだけの行は文書の参照情報として保持し、根拠となる主張の抽出結果には含めません。既に保存されたURLの主張行も削除・更新せず保持し、今回の考察に渡す集合から外します。

推論中の参照はD1/E1などの短いIDを使い、応答の参照を保存済みIDへ戻します。対応表はrawCallsのreferencesに残します。比較は一致点と相違点でそれぞれ両資料の引用を選びます。割合とパーセントポイントの取り違えも拒否します。否定の検査は主節を対象とし、セミコロン以降の例示中の否定を主節全体の否定とは見なしません。一般の構文・意味を完全に判定するものではありません。

## 信頼性と用途

発信元には言語・地域・媒体種別・立場を記録します。収集元のRSSと実際の記事発信者が違う場合、RSSの属性をそのまま記事発信者へ付与しません。主張ごとの分類は「裏付けが強い」「一定の裏付けがある」「未確認・判断保留」「重大な疑義あり」です。

本文との一致だけでは真偽を確定しません。同じ主体、同文、直接の参照依存は独立した証拠に数えず、別ドメインでも独立性は未確認です。数値差は観測条件の違いかもしれないため、疑義の確定ではなく候補として残します。自動的に「強い裏付け」を付ける経路はありません。

事実の裏付け、発信者の主張の理解、言説の分析、真偽の調査対象、結論での使用除外を区別します。低い裏付けの資料も調査対象として保存します。確信度は見解への主観的な順序尺度であり、真偽の確率ではありません。独立検証なしの新しい見解は最大0.45とし、ノートでは段階で示します。

## 失敗と再現

Ollamaの生成に失敗した場合、分野別の定型文で完成させません。rawCallsにプロンプトと応答、モデル、設定、文字数、取得できるトークン数、試行数、時間を保存します。失敗・不完全なノートはneeds_reviewで残し、成功した解釈として記憶や興味へ加算しません。通常のdeterministic実行と、古いノートは従来形式との互換性を保ちます。

Ollama通信はNode組込みHTTP(S)を用い、設定した単一の期限をヘッダー待ちと本文の両方へ適用します。従来fetchの別個のヘッダー期限による約303秒での早期失敗は、310秒遅延の対照試験で再現・修復を確認しました。応答128KiB上限、リダイレクト非追従、同じ期限内の限定再試行を維持します。`done_reason=length` の応答は、JSONとして読めても生成完了と認めず、`OLLAMA_OUTPUT_LIMIT` とraw応答を保存します。

追跡先はselected-items、article-content、source-summaries、research-model-output、analyze、verifyのチェックポイントです。research_page_attemptsとresearch_page_documentsには取得試行と原文が残ります。公開用書き出しはこれらの内部プロンプト・原文を含めません。

モデル生成や検査に失敗したノートを保存したサイクルはattentionとして記録します。文書が改訂されても、新しい考察に失敗した場合は以前の有効な記憶を検索対象に残します。子プロセスの監視とhealthの停止判定には共通の期限を使い、要約・考察の2回の呼び出しを見込みます。

日本語原文の明示的な否定の消失と、開催予定を開催済みへ変える要約も拒否します。「追加の資料が得られたら見解を下げる」というだけで観測内容が特定されない修正条件も拒否します。この条件に該当する過去の生成見解は、履歴に残したまま推論への再入力から除外します。これらは限定した表現の検査であり、一般の日本語の意味や因果関係を完全に判定しません。

自由記述の考察にも、年を含む開催日が資料の取得時点から1日を超えて先なのに、その同じ日付の行事を「実施した」「実施している」などとする出力を拒否する限定検査を適用します。根拠に開催予定が明記されている場合が対象です。仮定・予定・準備・別の過去日付は区別し、日付や取得時点が不明な場合はこの検査だけで判定しません。同じ条件に該当する保存済みの見解も、原文と履歴を削除せず新しい推論入力から除外します。年月日を明示しない誤読、一般の時制や意味の正しさは別途確認が必要です。

プロンプト21では、評価セットの作成手順を比較実験の結果に変えないこと、用途・適用範囲を検討すること、要約の各文を単一の引用IDの範囲に限定することを指示します。考察では、弱まる前提と見解を弱める観測を内部のJSON欄で先に整理し、修正条件へ結び付けます。保存する見解の形式は従来と同じです。本文の他の場所に存在する情報も、選択した引用に含まれなければその引用の要約には足しません。

引用に対応しない要約文は掲載対象から除外します。各資料に別の検査済み文が残り、他の重大な検査違反がない場合は、その文だけで処理を続行し、summaryWarnings・チェックポイント・Markdownに除外を記録します。有効な文が一つも残らない資料や、否定・予定・資料IDなどの他の違反は引き続き失敗です。すべての要約が不支持なら知識を追加しないことを回帰テストで確認しています。

同じ文書版の主張を再抽出するときは既存IDを再利用し、保存済みの分類・理由・時刻を上書きしません。「下がる」「弱まる」「狭まる」も見解修正の表現として認識します。構造検査で、観測が本当に見解を弱めるかまでは保証しません。別の短いモデル呼び出しによる論理照合は小試験で期待分類との一致が2/4だったため、自動承認には導入していません。

## 保存済み見解の意味診断

`scripts/review-research-consistency.ts`は、保存済みのanalysis.jsonから見解・反対仮説・修正条件を読み、既にインストールされたローカルOllamaモデルへ論理関係を問い合わせる明示的な診断コマンドです。データベースを開かず、ノート・記憶・成功判定を更新しません。出力先は`D:/AI/KousatsuData/Validation`配下の新しいディレクトリに限定し、既存の診断は上書きしません。

```powershell
node --import tsx scripts/review-research-consistency.ts --analysis D:/AI/KousatsuData/Validation/run/job-analysis.json --model qwen3:4b-q4_K_M --thinking true --output D:/AI/KousatsuData/Validation/new-review
```

`--analysis`は最大10件まで繰り返せます。モデルを自動取得せず、外部APIも使用しません。目的の推測、効果の仮説、価値の優先順位を区別して点検し、反対説明と両立する補完要因も区別します。応答の欠落・重複・未知のID・打ち切りは診断失敗として記録します。

すべての関係がweakensでも、結果は常に`advisory-only`、`semanticReview: pending`です。`requiresAttention: false`はモデルが特定の問題を指摘しなかっただけで、承認ではありません。診断器も支持と反証を取り違えるため、理由を保存済み見解と照合してください。通常生成の自動合否には接続していません。

## 実記事による受入検証

`scripts/validate-research-quality.ts`は本番と同じRuntime/ResearchEngineを使います。`--cases`には登録済みのRSSから取得できるsourceIdとurlを記します。自由な外部URLを取得するAPIは追加しません。

```powershell
node --import tsx scripts/validate-research-quality.ts --config D:/AI/KousatsuData/Validation/trial-config.json --cases D:/AI/KousatsuData/Validation/cases.json --output D:/AI/KousatsuData/Validation/TrialEvidence --phase trial
node --import tsx scripts/validate-research-quality.ts --config config/kousatsu-backend.json --cases D:/AI/KousatsuData/Validation/cases.json --output D:/AI/KousatsuData/Validation/ProductionEvidence --phase production
```

trialはValidation配下のデータ領域に限定し、publication.enabled=trueの設定では起動を拒否します。本番モードは私有Markdownの通常書き出しに加え、publication.enabled=trueなら既存の公開処理を呼び出します。モデル成功、構造検査、資料別要約、2件以上の資料、出典に結び付く比較を複数資料の受入条件にします。単一資料の取得・生成検査とは分けて記録します。全試行をacceptance.jsonへ残し、失敗を省きません。

このコマンドは明示的な手動受入試験です。通常の06/18/22時と日次3件の設定を変更しません。手動試験であることをacceptance-purposeへ記録し、通常と同じ日次実行枠を予約します。上限に達したら追加ジョブを作らず停止します。

自動検査に加え、出力を読んで数字・主体・時点・因果関係・反対仮説・条件・自然な日本語を確認してください。長期運転と外部の真偽確定は、短時間の受入試験とは別に追跡します。

## 2026-11-05 の品質監査・復旧

- 要約の読取範囲と本文省略は、モデルに推測させず実入力から記録する。出典に定員・料金等がないと断定する用途には使わない。
- 新しい要約は完成文を要求し、数値・割合・予定・否定に加え、明示された拠点と活動場所の取り違え、相関の因果化、一部の不確実性消失を検査する。数値単位は原文が同じ数値へ明示する単位との矛盾を検出し、原文で単位が省略されている場合は判定を作らない。
- 要約の修正は一度まで、同じ推論フェーズの期限内で行う。初回出力と拒否理由はrawCalls/validationIssuesへ残し、修正後も不正なら生成失敗とする。
- 明示的な将来日付の実施済み化は、古いdraftのverifyでも検査する。旧記憶の明示的な誤読は、元データを削除せず再利用から外す。
- 応答の受信後に解析・検査で拒否した場合もresponseReceivedを正しく記録する。受信と生成成功は別の状態である。

候補評価を構造化した版を、隔離3記事の試験後に本体へ採用。候補の評価・出典の主張・期待の理由・不確実性を保存し、選択と理由を同じ候補の記録から作る。同点は同じ優先度とする。評価基準は共通の結果への期待寄与、重み1、0〜4の暫定順序尺度であり、実測や成功確率ではない。比較の局所修正では候補評価を変更しない。未確認の比較仮説は既存の仮説管理に接続する。本体への採否と実記事の結果は D:/AI/KousatsuData/Reports/background-continuation-20261105.md を参照。構造・引用の自動検査と、内容の意味的な妥当性・独立した裏付けは区別する。

自律運転で確認した追加修正: 提示する引用と検査する引用に共通の選択処理を使い、各資料4件・3資料最大12件を保持する。9件で切って実在する後続引用を不明とする誤判定を修復。NASA APODの新レイアウトではExplanation本文を使い、クレジットだけのページを本文として採用しない。抽出器版4で古いキャッシュを再取得し、日次取得上限時には古い本文を再利用して成功扱いにしない。

## 2026-11-06 の継続研究と全件公開

プロンプト34/research-v11は、出典に対応する検査済みの過去見解・仮説・未解決点を未検証の履歴として入力する。生成文章を事実・独立証拠として扱わない。質問別の回答は現在の文書版と引用へ再照合し、研究課題の評価履歴に残す。文書に特定の記述があるかという引用付きの質問だけを記載確認のresolvedにできる。効果・因果・独立確認・優先判断は、部分回答があっても残る疑問を保持する。一般的な意味の一致を自動で証明するものではない。

課題の参照には実際に用いた主資料と追加資料の版を記録し、その資料を次回の調査へ引き継ぐ。質問の書式差だけによる重複作成を防ぎ、評価・見解改訂・仮説レビュー・次の質問を追跡する。APODという連載名や月名だけでは別天体を同じ問題に結び付けない。

公開の単位は出典URLではなく保存された考察ID。旧形式・要確認・同じ出典の別考察も状態を明示して公開し、品質だけを理由に除外しない。元ノートは変更せず、長い出典本文・内部実行記録・認証情報・個人の連絡先・ローカル保存先を公開版から除く。既存の公開本文は固定して保全する。
