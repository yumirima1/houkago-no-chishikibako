# 継続運転と検証

`config/kousatsu-backend.json` の `continuous: true / endsAt: null` で、停止するまで JST 06:00、18:00、22:00 に各1件を調査します。新規ジョブと実行開始の両方に日次上限3件があります。同一ジョブの再試行を別の生成枠として数えません。過去の操作定義・ノート・本文版は保持します。

将来8日間の枠を予約し、稼働のたびに延長します。前日以前の未処理枠は missed、予約範囲を越える休止期間は weekly_schedule_gaps に記録します。PCが停止していた全期間をまとめて生成しません。PCの電源設定は変更しません。

設定済みの出典では、identity指定にもかかわらず返るgzip/deflate/Brotliをストリームで復号できます。圧縮前の受信量と復号後の本文量はどちらも2MiBまで、全取得時間・DNS固定・許可ホスト・リダイレクト制限は維持します。一般の取得関数は既定で圧縮を拒否し、対応していない符号化も拒否します。

関心値はジャンル初期50（science は60）、テーマ初期30。Ollamaへの既存の1回の分析呼び出しで、記事の単語・概念を最大3候補まで評価します。各候補には原文の抜粋・保存版を付け、影響値-10～10、理由、確信度0～1、強化・低下・回避・中立、関連する関心と記憶IDを保存します。影響値はテーマの現在値0～100や事実の真偽とは別です。AIの理由も未検証の意見として扱います。

変化は影響値×確信度÷2を0.5単位で丸め、同じテーマの1記事分は±6まで。ジャンルには同記事の評価の平均を反映します。AI応答が空・壊れた・不足・timeoutの場合はfailedとして記録し、架空のAI評価や加算を作りません。モデルを要求していない決定的分析と、旧形式記録の受領は、従来のルール方式であることを区別します。Ollamaの出力上限は1600トークン、既存の180秒期限は維持します。

関連観測のない7日ごとに5減衰する既存規則を再利用します。同じ文書・本文の再処理では二重加算しません。活動中のテーマは最大50。新しい概念のために低関心テーマを活動対象から外す場合も、元の値・根拠・履歴を保持します。新しい関連情報で再び対象にできます。

枠ごとに最大4出典を選び、関心値に応じて候補走査2～12件、本文調査1～2件を配分します。探索率25%で選外の出典を含めます。最大関心時の追加本文調査も同じ枠内で実施します。モデル生成は1件です。抽選と配分を SQLite の research_slot_plans に固定し、再起動時の抽選し直しを防ぎます。

前回の未解決の問いは research_inquiries に保存し、関連する新しい記事が来ると選択とモデル入力に接続します。1問につき試行3回、資料がない枠も3回で資料待ちとします。新しい関連資料の受領だけが再開理由です。仮説レビューだけで全ての問いを解決扱いにしません。問いに直接答える自動検証は今後の課題です。

出典主張は引用・URL・保存版に結び付け、保存済みの関連資料から数値の食い違い、同文転載、同一発表主体を検出します。異なるドメインだけでは独立した裏付けと認定しません。これは保存資料の照合であり、インターネット全体の独立した事実確認ではありません。

本文の実質的な変更があり、関連する未解決課題とキャッシュ期限の条件を満たした時は、同じURLでも再評価できます。既に公開した旧考察は残し、新考察から旧考察を参照します。単なるRSS再取得や本文不変では生成しません。

## 運用コマンド

プロジェクトルートで実行します。

```powershell
npm run kousatsu:backend -- health
npm run kousatsu:backend -- audit
npm run kousatsu:backend -- status
npm run kousatsu:backend -- backup
powershell -NoProfile -File scripts/kousatsu-task.ps1 -Action Status
```

health は正常時のみ終了コード0を返します。audit はデータを書き換えず、取得元、未完了ジョブ、関心、問い、最新10サイクル、公開対象外の理由、Git送信と公開URL検査を表示します。履歴全体は autonomy_runs、各ジョブの checkpoints、Logs のJSONLに残ります。関心と問いの変更は Memory の interest-event / inquiry-event ファイルにも保存します。これらはローカル情報です。

```powershell
npm run kousatsu:backend -- public-verify
npm run kousatsu:backend -- public-retry
```

公開は既存の main → GitHub Actions → GitHub Pages を使います。送信と公開URL到達を分け、実際のsnapshot・全ノートJSON・Markdownのハッシュ一致で到達を記録します。自動再試行は5分間隔・3回まで。稼働中の所有者をリースで保護し、失効したrunningは中断として回復します。最終試行の中断はfailedで停止し、public-retryで明示的に再開できます。public_attempt_eventsは中断・失敗・再試行・最終結果を削除せず保持します。送信済みデータの再照合では同じ記事を増やしません。空の書き出しや既存公開ノートの欠落は拒否します。

停止時は Stop、現在の処理完了と Status を確認し、再開時は Start を使います。既存のタスクスケジューラはログオン時と毎時の起動、重複起動の抑制、上限付き再起動を担当します。子プロセスの期限、サイクル・ワーカー・ジョブのリース、チェックポイントによって途中停止から復旧します。

数日後に health / audit と GitHub Actions を再確認し、日次3件以内、過去枠の状態、本文取得失敗、モデル失敗、未完了ジョブ、公開到達失敗、ディスクとDB容量を確認してください。短時間の試験だけで数日間の連続運転を証明したことにはなりません。
