# 観察記録のブラウザ保存と復旧

観察記録はブラウザのlocalStorageに保存する。調査エンジンのSQLiteとMarkdownノートとは別の記録であり、ブラウザに保存された観察を自動でサーバーへ移送しない。

## 読込と保存

- hookの`hydrated`が真になるまで、観察記録の保存と自動キャラクター選択を行わない。読込失敗・不正JSON・不正スキーマは空の新規データとして扱わず、既存値を保持して保存を停止する。
- 既存の`houkago.observation.logs`、`houkago.observation.relationships`、`houkago.observation.selectedSubject`は移行元として読込み、その後も削除・上書きしない。
- 最初の操作前に`houkago.observation.snapshot.v1`へ元の状態を保存する。以後は`houkago.observation.operation.v1.<観察ID>`へ1操作ずつ追記する。選択・ログ・関係値の増分は1つのJSONに含まれるため、1回の`setItem`で原子的に保存される。
- 記録順には単調なsequenceを使用し、同時操作は時刻とIDで順序を確定する。実際の観察時刻は変更しない。別タブが同じsequenceを使っても、異なるキーへ追記するため双方の記録は残る。storageイベントと次の操作で最新のjournalを再読込する。
- 関係値はbaselineと操作履歴から再計算する。同じ観察IDの再保存は同一内容なら冪等、異なる内容なら競合として停止する。Reactのstate updater内には保存処理を置かず、StrictModeの再実行で保存回数を増やさない。
- 保存に失敗した操作は画面の記録・選択・関係値にも反映せず、エラーを表示する。原因を解消して再操作できる。読込失敗後は「保存状態を再読込」で安全に再試行できる。

baselineだけを書いたところで処理が中断されても、その中身は元の状態である。journal書込前の失敗で部分的な観察を作らず、書込後に表示が中断しても次の読込で保存済み操作を復元できる。書込後の再読込が失敗した場合は、保存済みの当該操作を表示し、警告を出して以後の保存を停止する。再読込で全journalを確認するまで再操作による重複を作らない。JSON破損や不明な形式は黙って読み飛ばさず、既存値を保持する。

## 制約と将来の保守

全操作を保持し、従来の40件制限による保存時の切捨ては行わない。既存UIは直近の必要件数だけ表示する。localStorageにはブラウザごとの容量制限があり、読込・追記時の再生コストは履歴数に比例する。容量不足時は既存記録を残して新規保存を停止する。現段階では自動削除・自動圧縮をしない。

長期運用の次段階では、全キーの安全なエクスポートと検証済みバックアップを先に用意し、操作ID・件数・関係値の一致を検証したうえでSQLiteや新snapshotへの移送・圧縮を設計する。確認できないjournalを削除して保存を再開してはならない。旧版アプリとの同時使用は、旧版が追記journalを理解しないため未対応である。旧3キーは復旧用に残るが、journal導入後の新しい操作は旧版UIには表示されない。

BGM・環境音・部屋の案内・表示モードの設定もストレージ例外を捕捉する。BGMと環境音は読込に成功するまで保存せず、初期読込だけでは既存値へ書き戻さない。設定保存に失敗した場合はセッション内の操作を続け、未保存を画面に表示する。音声の実再生を保証するものではない。

## 検証

`npm.cmd run test:kousatsu`に含まれる`observation-hydration.test.ts`は制御schedulerとメモリストレージで17件を検証する。読込前操作、初回、再読込、順序、破損JSON、保存失敗・再試行、保存後読込失敗、40件超の保持、別タブ競合、同一IDの冪等性と競合を含む。

実React DOMの補助検証は、プロジェクト依存を変更せず別ディレクトリにReact/React DOM（アプリと同じ版）とjsdomを用意して実行する。

```powershell
node scripts/verify-observation-react.mjs --dependencies <隔離ディレクトリ>
```

React 19.2.4・jsdom 27.0.0でStrictMode、実際のListeningRoom・観察hook・音声設定hook・部屋の案内を検証した。調査端末ではノート選択、古い応答の無視、Markdownのテキスト表示、アクション失敗、runtime応答順を検証する。3Dシーンはstub、音声はfixtureに置き換える。jsdomには描画ブラウザのWebGLや実音声再生がないため、それらとレイアウトの実環境検証は別途必要。
