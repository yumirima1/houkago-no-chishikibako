## 主な傾向

### 1. かなが相槌マシンではないが、別の型に寄る

単純な「なるほど」「たしかに」だけの相槌はほぼ出ていない。

一方で、次の型が繰り返される。

- 理屈が勝ちすぎてない？
- 分かったことにされると、置いていかれる
- 半分しか納得してない
- 戻り方が雑だけど

かなは受け身ではないが、「違和感テンプレ」を言う役になりやすい。

### 2. タルタルは講師化しにくいが、足場文が残る

現在のDraftは長い講義にはなりにくい。

ただし、次の足場文が本文に残りやすい。

- 説明っぽくなりすぎないように言うと
- たぶん一個の理由だけじゃない
- 気持ちと仕組みの間に、ちょっとした引っかかりがある
- 正解を出すというより

これは「講師化」ではなく「生成器の説明文が会話に残る」問題である。

### 3. 会話が短すぎる

平均544文字、平均11.6行で、20分通常回の原稿としては明確に不足している。

現段階のDraftは最終原稿ではなく、会話の骨格として扱うのが妥当である。review-scriptでは「短い原稿量」を警告する必要がある。

### 4. 同話者連続が多い

26件すべてで同話者連続が発生した。

平均3.31回で、特に #033, #042, #044, #050 は5回発生している。

Skeleton の speaker 指定と Draft の follow-up 展開が噛み合わない場面がある。レビューではテンポ確認を強める。

## review-scriptへ反映した警告

- 原稿量不足
- 疑問不足
- 感情不足
- 小さな笑い不足
- 深夜の放送室の気配不足
- Draft由来テンプレ過多
- 脱線が存在するが少なすぎるケース
- Draft Script Engineの足場文残り

## SHOW_BIBLEへ反映した判断基準

- タルタルらしさ
- かならしさ
- 会話テンポ
- 夜の空気
- 不安と反論の扱い
- 禁止口癖と弱いDraftの兆候

## 次の改善案

1. Draft Script Engine の発話テンプレートを「役割別」から「温度別」に分ける。
2. Skeleton に conversationTemperature を追加し、脱線、沈黙、笑い、説明量の比率を制御する。
3. Episode Seed Engine に cooldown と correlation を入れ、同じ小物、同じボケ、同じ比喩の再利用を抑える。
4. review-script の警告を外部JSON化し、SHOW_BIBLEの思想と実行ルールの対応を見やすくする。
