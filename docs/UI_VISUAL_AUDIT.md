# UI Visual Audit

更新日: 2026-06-04

## 対象

ローカル dev server でトップページを確認した。

- PC幅: 1280 x 720
- スマホ幅: 390 x 844

## 確認結果

### PC幅

良い点:

- 最初の視界で、背景、CRT、NOW PLAYING、ON AIR/OFF AIR が見え、深夜の放送室として成立している。
- episode-017 が自然に主役になっている。
- 右側の Audio / BGM / Ambient controls は存在感があるが、中央の放送室体験を壊してはいない。
- 背景のCRT Monitor Clock は中央巨大時計ではなく、部屋の一部として見えている。

気になった点:

- 下部の「タグ検索」「話を選ぶ」は便利UIの匂いが強く、少し一覧サイトへ戻りやすい。
- 初期表示で「次回更新予定: 計算中」が一瞬出ると、放送局の空気よりアプリ感が出る。

対応:

- 「タグ検索」を「放送記録の索引」へ変更。
- 「話を選ぶ」を「放送記録」へ変更。
- 次回更新予定を初期 state で計算し、「計算中」を出さないようにした。

### スマホ幅

良い点:

- 1画面目で「NIGHT BROADCAST ROOM」「放課後の知識箱」「CRT MONITOR CLOCK」「#017」が見える。
- episode-017 はスマホでも主役になっている。
- 背景モード、放送を聴く、部屋だけ見るの導線は大きすぎず、最低限に収まっている。

気になった点:

- 長い説明文が右端で窮屈に見える箇所があった。
- mobile media query の `station-first-view` 幅指定が親の padding と噛み合わず、右端が詰まる可能性があった。

対応:

- episode description に `break-words` を追加。
- mobile の `station-first-view` を `width: 100%; max-width: 100%;` に戻した。

## 総評

現状のトップページは、便利な一覧サイトではなく、深夜の放送室として成立している。

ただし、下部の検索・一覧系UIは少し便利さへ戻りやすい。今後も「タグ」「一覧」「検索」という言葉を前面に出しすぎず、「放送記録」「索引」「今夜の放送」の語彙へ寄せる。

## 次のUI課題

- スマホで Ambient Controls を開いた時の圧迫感を確認する。
- 背景モード中の controls が小さい端末で重ならないか確認する。
- 放送記録のカード数が増えた時、一覧サイト感が戻らないように、最新回と過去回の視覚差を保つ。
