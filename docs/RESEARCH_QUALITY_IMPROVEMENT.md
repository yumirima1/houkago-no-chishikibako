## 取得・記憶・復旧の流れ

永続ジョブ → RSS取得 → 許可された原記事・参照リンクの本文取得とキャッシュ → 文書版と取得区分を一つのトランザクションで固定 → 原文の主張抽出 → 関連候補の選別 → 問いの選択 → Ollamaの構造化提案と引用検査 → ノート → 独立した構造・引用検査 → Markdown保存 → 記憶・評価履歴・知識ベースの出力。

本文取得前後も既存のジョブリースとチェックポイントを使用する。本文版を保存した後の停止は、同じチェックポイントから再開し、再取得や二重ノート作成を避ける。取得失敗でもフィードや旧版を失わず、取得範囲と失敗理由を記録したノートを保存する。

許可ホスト、DNS固定、公開IP検査、全リダイレクトの検査、15秒の通信期限、2MiBの応答制限を既存通信処理から再利用する。robots拒否・取得不能時は迂回しない。大きなcrawl-delayは処理予算内に短縮せず取得を保留する。成功・失敗・拒否をキャッシュし、開始済みの試行も数えて1URL1日3試行までに制限する。プロセス停止で試行上限をリセットさせない。

過去の仮説の評価は、事前に保存された支持・反証の観測条件と、新しい版の原文引用が完全一致する場合だけ変更する。支持・反証ともある場合や一致しない場合は未判定。評価は出典の記述による候補であり、独立した裏付けではない。`research_hypothesis_reviews` と `Hypotheses/evidence-review-*.md` に追記し、旧記憶を上書きしない。
