# 考察箱の部屋と読書画面（2026-10-28）

現在の3Dルームは2階の一室を切り取った構成。ベッドと薄型モニターを置かず、
既存の湾曲ガラス・厚い筐体・脚・通気口を持つCRTを主役にした。
補助CRTは同じモデルの55%スケール。左の側壁と奥の壁、床の厚み、巾木を残し、
前面と屋根を省略して角と接地を見せる。建物の下階や階段は作らない。
本棚は側壁、電子ペーパー2枚は奥の壁に段違いで取り付けている。

外の地面は室内床から3.6m下。道路・車・線路・電車・建物はそれぞれ屋外に配置し、
既存の窓の開口ステンシルで室内へはみ出さないようにする。車と電車は、窓から
見えない範囲で折り返す。天候・夜景は既存の福岡市のOpen-Meteo取得を使用。

## 窓と音

- 初期状態はhydration後に一度だけWeb Cryptoで抽選。窓は40%で開き、音楽は60%で
  再生を選ぶ。夜の閉じた部屋を少し多くし、ローファイが流れる組み合わせを多めにする。
  4通りの組み合わせがあり、操作や天候更新で引き直さない。再読み込みでは新しく選ぶ。
- 窓は現在位置からゆっくり補間し、途中で逆操作しても飛ばない。枠・ガラス・雨粒が
  一緒に動く。UIには開閉中を表示し、実際の枠が止まると完了状態になる。
- Web Audioによる既存のオリジナル合成音を再利用。音楽だけに音量スライダーを設ける。
  雨は天候に従い、街の音とともに窓の開閉で自動調整。外音全体は停止・再開できる。
  外音バスは0.22〜1、ローパスは850〜12,000Hzを550msでフェードする。
- 自動再生をブラウザが認めれば選ばれた音を開始する。認めない場合は音量0のまま、
  「音は待機中」「音を有効にする」と表示する。resumeが未解決のままになるブラウザも
  450msで待機状態へ移し、再生中と表示しない。ユーザー操作で同じ音源を再利用する。
  音量0は正確に無音になり、音楽の停止は外音を止めない。

## 端末と読書

- PCはCRTのクリック、キーボード、マウス、キーボード操作から端末を開く。
- スマートフォンでは部屋を見せてから、机上の3D端末が浮き上がって手前へ移動する。
  カメラは固定。1.5秒の移動が終わり、少し止まってから専用のスマートフォンUIを表示。
  戻ると端末は机へ帰り、同じ接続中に自動で何度も開き直さない。
- 小画面は専用のホーム・アプリ選択・一覧を使う。PCのベゼルやDockを縮小しない。
- 一覧を選ぶと一覧・Dock・端末枠を外し、アプリ内の全画面読書画面へ切り替える。
  本文は16px以上、十分な行間と最大780pxの読書幅。端の戻るボタンは44px以上。
  一覧へ戻ると検索・スクロール・選んだ項目のフォーカスを復元する。
- 見出し、段落、引用、箇条書き、コード、通常のHTTP(S)リンクを安全なReact要素で表示。
  生HTMLとJavaScriptリンクは実行しない。タイトルのHTML文字参照は表示時だけ復号。
  保存されたMarkdown、ID、出典、関連する前の考察、ダウンロードは変更しない。
- reduced-motionでは窓とカメラ・端末の移動を省略し、短いフェードと必要時の描画を使う。

## 検証手順

`npm run typecheck`、`npm run lint`、`npm run test:kousatsu`、通常ビルド
`npm run build -- --webpack`、`npm run build:pages`、`node scripts/verify-pages-artifact.mjs`。
同じロックファイルの検証済み依存を隔離worktreeから参照するローカル環境ではwebpackを
指定する。CIは既存どおりクリーンなnpm ciと静的ビルドを使う。依存の追加・更新はない。

ブラウザ検証は既存の`npm run test:pages`。PC・390px/320pxのタッチ操作、本文と戻る、
出典・ダウンロード、初期4通り、途中反転、外音自動制御、音量0、音声の待機と再試行、
バックエンド障害、キャンセルされた本文の遅延応答と安全な表示を検査する。
Threeの標準devtools通知をテスト側だけで観測し、端末とカメラの実座標を比較する。
実AudioContextとAnalyserNodeをテスト側だけで観測し、音の出力と正確な無音を確認する。
本番コードにテスト用の起動フラグやグローバル変数は追加していない。

公開は既存のmain→GitHub PagesとVercelを使用。Pagesは公開アーカイブを静的に読む。
Vercelのローカル専用APIの403制限をUIの都合で解除しない。バックエンド、保存先、
公開データ形式、研究・運用処理は変更しない。

実際のPCブラウザと、同ブラウザでのスマートフォン／タッチエミュレーションを区別して
報告する。物理的なスマートフォン、Safari、スピーカー越しの音質評価を確認済みとはしない。
